# 源文件与恢复清单

本文件记录项目可恢复来源和长期保留资产，避免关键版本只存在于聊天记录、临时目录或失效链接中。

## 1. 当前可信源码

当前可运行源码以 GitHub 仓库 `main` 为准：

```text
https://github.com/kachekakaka/bili_workspace
```

`main` 必须直接包含可审查的 Python、前端、测试、Docker、Windows 启动器源码和文档，禁止使用 Base64 分片或运行时恢复源码。

重要恢复点应额外保留：

```text
源码 ZIP
完整 Git Bundle
对应提交 SHA（既有历史版本也可记录 tag）
验证记录
SHA256SUMS.txt
```

## 2. Windows 打包快照

最近一次由维护者手工晋升的 Windows amd64 打包快照及其稳定身份直接以普通 Git 对象保存在：

```text
dist/bili-workspace-launcher-0.7.0.exe
launcher/current-build.json
```

版本、`build_id`、大小、SHA-256 和资源清单摘要的唯一快照真源是 `launcher/current-build.json`；运维文档不复制这些易漂移值。该快照可能落后于 `main`，不能用它证明最新源码已经打包。当前 schema 1 记录没有源码 commit；下一次明确晋升产生的 schema 2 记录还必须包含干净完整 `source_commit`、`source_dirty=false` 和两类 EXE 检查标志。

运行资产包含：

```text
Python 3.11 和锁定依赖
BBDown 1.6.3
FFmpeg 7.1.1
第三方许可证
包内逐文件资源清单和对应源码/重链接材料
```

EXE 启动时在同级 `resources/<build_id>/` 展开并校验内置资源，实际配置和业务数据只写用户选择的数据根。恢复时不需要复制旧 `.venv`、`.runtime`、`BBDown_portable` 或 Portable Python packs。

## 3. 当前运行数据

Windows：

```text
<data-root>/config/                 配置、网络安全设置、标签和 BBDown.data（敏感）
<data-root>/userdata/               SQLite、任务、删除历史、索引、日志、缓存和临时状态
<data-root>/downloads/              媒体文件
<launcher-dir>/launcher.json        可重建控制状态，可丢失后重新选择数据根
```

Docker 运行宿主机：

```text
CONFIG_DIR
USERDATA_DIR
MEDIA_DIR
```

容器内对应：

```text
/data/config
/data/userdata
/downloads
```

完整恢复必须保留数据库和媒体的一致性。在线复制 SQLite 时同时保留 `.db`、`-wal` 和 `-shm`；具体数据职责和恢复步骤以[备份、恢复与旧版本迁移](备份恢复与V0.4迁移.md)为准，不在本清单重复维护。

## 4. 重要恢复点建议保留

```text
1. 可直接审查的 GitHub main 源码树
2. 对应提交 SHA
3. 源码 ZIP
4. 完整 Git Bundle
5. Windows 打包快照 EXE、配套构建记录和校验和
6. 受保护的仓库外数据根备份
7. Docker 镜像打包说明、离线包及其独立校验和
8. SHA256SUMS.txt
9. 重要变更验证记录
10. 当前需求、设计和字段契约
11. 当前文档与归档索引
```

Git Bundle、Windows 完整恢复包、运行数据备份和 SHA256SUMS 应额外保存到用户自己的 NAS 或云盘；GitHub 不是唯一备份。

## 5. 恢复优先级

1. 从 GitHub `main`、已验证提交或既有历史标签恢复源码；
2. 核对 `launcher/current-build.json` 与打包快照 EXE 的大小、SHA-256 和平台；schema 2 还应核对 `source_commit` 对应的可恢复提交；
3. 恢复同一时间点的数据根 `config`、`userdata` 和 `downloads`，其中已包含敏感的 `BBDown.data`；
4. 只有该快照支持恢复库的 schema 时才启动 EXE 并重新选择数据根；Docker 镜像先按[打包与离线交付手册](Docker镜像打包与离线交付.md)核对平台、镜像 ID 和校验和；
5. 真实 Docker/QNAP 上线按未来另行确认的部署方案执行；
6. 核对作品、标签、删除历史、分组、任务和播放记录。

任何备份或可分发恢复包都必须排除真实登录 Cookie、管理员初始化令牌、未加密密码和用户媒体，除非它本身就是受保护的私人运行数据备份。
