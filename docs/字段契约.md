# 字段契约

本文件是数据库、API、配置、跨进程和序列化边界中字段所有权、名称、类型、空值、默认值、映射与兼容规则的唯一长期真源。行为语义见[需求文档](需求文档.md)，实现数据流见[设计文档](设计文档.md)。

## 1. 通用约定

- API JSON 字段使用 `snake_case`；未声明的请求字段默认拒绝。
- 成功响应至少包含 `{"ok": true}`，有主体时使用 `data`；列表端点可以增加 `total`、`limit`、`filters` 或 `grouped`。
- 失败响应至少包含 `{"ok": false, "error": <字符串>}`，稳定分类可增加 `code`。
- ID 在 API 中均为非空字符串；时间戳在 SQLite 和 API 中使用 Unix 秒数，允许历史记录的可选时间为 `null`。
- 空字符串表示“没有选择”或“使用默认值”时必须由具体字段明确允许，不能与 `null` 任意互换。
- 客户端提交的拥有者、角色和权限字段不具有授权效力，服务端认证上下文始终覆盖它们。

仓库当前 `launcher/current-build.json` 是 schema 2 正式快照记录，必须与 `dist/bili-workspace-launcher-0.7.0.exe` 成对存在且身份一致；在维护者下一次明确晋升前不改写。它除版本、`build_id`、平台、文件名、字节数、SHA-256、资源清单 SHA-256、Python/PyInstaller/PySide6 版本、构建时间和 EXE 自检标志外，还记录构建时源码 commit 与脏状态；它只能证明该快照身份，不能代表 `main` 最新源码。

新候选记录和未来正式快照记录使用 schema 2，并保留 schema 1 的上述公共身份字段：

| 字段 | 类型与规则 |
| --- | --- |
| `schema_version` | 固定为 `2` |
| `artifact_kind` | `candidate` 或 `snapshot` |
| `source_commit` | 构建开始时完整 40 位小写 Git `HEAD` |
| `source_dirty` | 候选可为 `true`；正式快照必须为 `false` |
| `exe_self_check_ran` | 必须为 `true` |
| `exe_runtime_smoke_ran` | 必须为 `true`，表示 EXE 已在全新仓库外临时数据根验证本机健康响应、同一 `build_id`、当前数据库 schema 和根页面 |

正式快照只能从干净、已提交且构建期间未变化的 `HEAD` 生成；候选的 schema 2 记录只位于 `build/` 的任务目录，不得替换规范记录。`build_id` 仍由实际内嵌资源、应用/Web/Docker 上下文和启动器输入确定，排除时间与输出文件，不能用 `source_commit` 代替内容身份。

| 文件或字段 | 类型与规则 |
| --- | --- |

| `BILI_VERIFY_RUN_ROOT` | 只供隔离验证入口使用；必须通过所有权、直接父子关系、重解析点和 containment 校验，不能作为普通启动时改写数据根的后门 |

T-PROJECT 不写 `test_id`、结果 schema、保留期或 GC 元数据；本地运行结束后精确清理，CI 浏览器 run 只保留到 Artifact 上传完成。T-DOCKER 的 PowerShell 手工入口使用独立最小交接记录，不读取、迁移或删除既有仓库外证据。

### T-BILIBILI-LIVE 短期字段

| 文件或字段 | 类型与规则 |
| --- | --- |
| `<git-common-dir>/bili-workspace/automatic-live-test.json` | 当前仓库本地长期授权；UTF-8 JSON object，字段必须恰为 `schema_version=1`、`authorization="automatic_live_test"`、`project_id="bili_workspace"`、绝对 `credential_source` 与绝对 `test_root`。同一 Git common directory 的 worktree 共享，clone、commit 和 push 不携带；路径或日常数据根身份漂移时失效 |
| `.bili-workspace-live-test.json` | 凭据源根内固定场景文件；UTF-8 JSON object，字段必须恰为 `schema_version=1`、`kind="bili-workspace-live-test"`、正整数字符串 `creator_uid`、恰好 8 个唯一合法 BV 的 `download_bvids`；运行器只读且不得创建，该文件不单独授予仓库长期真测权限 |
| `BILI_TEST_ROOT` | 显式真链入口必填绝对路径；自动入口改用仓库本地授权的 `test_root`。两者均不得位于 `%LOCALAPPDATA%`，不得与工作区或凭据源互相包含，不得经过重解析点 |
| `results/summary.json` | schema 1 短期摘要；至少含 `test_id="T-BILIBILI-LIVE"`、run 与 `source_identity`、按目标分别使用的 `candidate_identity` 或 `tool_provider`、`impact`、`target`、UID/BV、阶段与最终状态、计数、耗时、增长、结构漂移、停止原因、安全错误分类及受控中文 `reason`；禁止凭据源路径、原始异常正文及任何秘密 |
| `results/raw-public/index.json` | 只登记本次公开响应的 `kind` 与 run 内文件名，不保存 URL、查询参数、请求或响应 header |
| `results/fixture-candidate/*.json` | 完整结构的确定性脱敏候选；保留非动态字段名、嵌套、类型、null 与不同数组元素结构，真实值替换为固定有效占位值；真实值出现在字段名时安全停止，普通真测只写 run、不写仓库 |
| 候选 live-session 文件 | 固定为 `results/candidate-live-ready.json`、`results/candidate-live-result.json` 和 `runtime/candidate-live.stop`；只接受候选 EXE 所在 `run/candidate` 的父级所有权与真链摘要，不接受凭据源路径；就绪与结果记录必须回显外部编排器一次性 256-bit 会话令牌的 SHA-256，明文令牌只经候选进程环境传入并在启动后移除 |

`summary.json` 的 `status` 只使用 `passed`、`failed`、`blocked`、`inconclusive`、`not_run`。`fixture_drift` 非空且产品行为尚可时仍为 `inconclusive`；只有显式 `refresh-fixtures` 维护动作可以把已验证候选写入 `SoftwareTesting/bilibili_live/fixtures/`。成功 run 删除全部凭据副本，其他状态保留整个 run；满 72 小时不触发自动删除。

## 3. 目录与进程环境字段

Windows 后端的路径字段由启动器注入；Docker/服务管理器可显式提供对应环境变量。非 Docker、非启动器进程不回退到仓库内数据目录。

| 字段 | 默认值 | 规则 |
| --- | --- | --- |
| `BILI_APP_MODE` | `auto` | 运行模式；Docker 显式覆盖为 `docker` |
| `BILI_HOST` | 空 | 空值回退到配置文件；Docker 固定传入 `0.0.0.0` |
| `BILI_PORT` | 空 | 空值回退到配置文件；有效范围 1–65535 |
| `BILI_CONFIG_DIR` | Windows 显式注入；Docker `/data/config` | 配置和标签目录 |
| `BILI_USERDATA_DIR` | Windows 显式注入；Docker `/data/userdata` | SQLite、任务、日志、缓存和临时状态目录 |
| `BILI_DATABASE_PATH` | `<userdata>/bili_workspace.db` | SQLite 主文件 |
| `BILI_MEDIA_DIR` | Windows 显式注入；Docker `/downloads` | 永久媒体目录 |
| `BILI_CACHE_DIR` | `<userdata>/cache` | 可重建缓存 |
| `BILI_TEMP_DIR` | `<userdata>/tmp` | 临时状态和设备导出目录 |
| `BILI_BBDOWN_DIR` | Docker/测试兼容字段 | 非启动器下载适配器目录；Windows EXE 使用下方拆分字段 |
| `BILI_AUTH_REQUIRED` | `true` | 兼容字段；`false` 不再关闭网站登录 |

Windows EXE 的内部后端子进程额外使用以下封闭字段。它们由启动器生成并逐项与会话 journal、`build_id`、数据根和已展开资源根核对，不是用户可编辑配置：

| 字段 | 启动器注入值与规则 |
| --- | --- |
| `BILI_LAUNCHER_CHILD` | 固定为 `1`；缺失时拒绝内部 `--run-backend` 入口 |
| `BILI_DISABLE_LEGACY_MIGRATION` | 固定为 `1`；EXE 不扫描或搬运旧仓库数据 |
| `BILI_BBDOWN_TOOLS_DIR` | `resources/<build_id>/windows-tools`；只读、已校验工具目录 |
| `BILI_BBDOWN_DATA_DIR` | `<data-root>/config/bbdown`；`BBDown.data` 唯一凭据目录 |
| `BILI_APP_RESOURCE_ROOT` | 已展开资源中的 `docker-context`；Web、默认模板和 Docker 构建上下文只从这里读取 |
| `BILI_BUILD_ID` | 12 位小写十六进制构建身份；必须与资源清单及会话 journal 一致 |
| `BILI_LAUNCHER_TOKEN` | 每次后端会话生成的 32 位十六进制随机令牌；journal 只持久化 SHA-256，不写明文；子进程完成 journal、路径与资源身份核验后立即从环境删除，不能再被 BBDown、FFmpeg 或其他后代进程继承 |
| `HOME` | `<data-root>/userdata/home` |
| `XDG_CACHE_HOME` | `<data-root>/userdata/cache` |
| `DOTNET_BUNDLE_EXTRACT_BASE_DIR` | `<data-root>/userdata/cache/dotnet`，约束 BBDown 的 .NET 单文件展开缓存 |
| `TEMP`、`TMP`、`TMPDIR` | `<data-root>/userdata/tmp` |

Docker Compose 把 `CONFIG_DIR`、`USERDATA_DIR`、`MEDIA_DIR` 映射到容器固定路径 `/data/config`、`/data/userdata`、`/downloads`。宿主机路径必须是非空目录路径，且不会写回 Git 模板。

| 运行字段 | 源码默认 | Docker 宿主字段及默认 | 含义 |

| `BILI_COOKIE_SECURE` | 空 | `COOKIE_SECURE=false` | 显式布尔值；HTTPS 部署设为 `true` |
| `BILI_HSTS` | 空 | `ENABLE_HSTS=false` | 仅在 HTTPS 已验证后启用 |
| `BILI_EXPORT_TTL_SEC` | `86400` | `EXPORT_TTL_SEC=86400` | 中断设备导出的保留秒数 |

| `BILI_DOWNLOAD_CONCURRENCY` | `1` | `DOWNLOAD_CONCURRENCY=1` | 下载 worker 上限 |
| `BILI_TRANSCODE_THREADS` | `0` | `TRANSCODE_THREADS=0` | `0` 表示由实现选择线程数 |
| `BILI_BOOTSTRAP_TOKEN` | 无模板值 | `BOOTSTRAP_TOKEN=` | 非回环首次初始化的一次性秘密 |

Docker 交付字段：

| 字段 | 新部署默认 | 兼容规则 |
| --- | --- | --- |
| `BILI_IMAGE` | `bili-workspace:local` | 本地构建的镜像名；既有 GHCR 值不被模板更新覆盖 |
| `BUILD_LOCAL` | `true` | `true` 从当前检出源码构建；既有部署需手动切换 |
| `PULL_IMAGE` | `true` | 仅在 `BUILD_LOCAL=false` 时生效；`true` 从仓库拉取，`false` 使用已经由 Container Station 或 `docker load` 导入的本地镜像 |
| `PUID` | `1000` | 容器进程用户 ID；必须为非零数字 |
| `PGID` | `100` | 容器进程组 ID；必须为非零数字 |
| `TZ` | `Asia/Shanghai` | 容器时区 |
| `BIND_IP` | `0.0.0.0` | NAS 端口绑定地址 |
| `HTTP_PORT` | `3398` | NAS 暴露端口，1–65535 |

`BUILD_LOCAL` 与 `PULL_IMAGE` 只接受显式布尔值。离线导入模式必须设置 `BUILD_LOCAL=false`、`PULL_IMAGE=false`，启动脚本会先确认 `BILI_IMAGE` 已存在于本地并以 `--no-build` 启动，既不访问镜像仓库也不从源码意外重建。

`PUID` 或 `PGID` 为零时配置检查必须失败；容器入口还会根据实际 `id -u` / `id -g` 再次拒绝 root，不能通过直接调用 Compose 绕过。

## 6. 标签配置字段

`config/tags.json` 的根对象包含 `palette_version: integer` 和 `tags: array`。每个标签对象包含：

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `name` | string | 标签显示名；关系以 SQLite 中的规范记录为权威 |
| `color` | string | CSS 十六进制颜色，例如 `#d4a017` |
| `enabled` | boolean | 是否在可选标签中显示 |

当前模板标签依次为“夯”“顶级”“人上人”“NPC”“不要”，用户实际文件可以新增、修改或禁用标签，模板同步不能覆盖这些选择。

## 7. 下载请求字段

`DownloadRequest` 拒绝额外字段：

| 字段 | 类型与默认 | 规则 |
| --- | --- | --- |
| `urls` | `string[] = []` | 单项最长 4096 字符 |
| `bvids` | `string[] = []` | 单项最长 4096 字符 |
| `items` | `DownloadItem[] = []` | 与前两者合计最多 100 项 |
| `force` | `boolean = false` | 普通用户始终覆盖为 `false` |
| `group` | `string = ""` | 分组显示名；普通用户覆盖为空 |
| `group_id` | `string = ""` | 稳定分组 ID；普通用户覆盖为空 |
| `destination` | `"library" or "device" = "library"` | 普通用户覆盖为 `device` |
| `min_height` | `integer or null = null` | 非空时必须属于允许集合 |

`DownloadItem` 至少提供非空 `bvid` 或 `url`：

| 字段 | 类型与默认 | 规则 |
| --- | --- | --- |
| `bvid` | `string or null` | 与 `url` 至少一个非空 |
| `url` | `string or null` | 与 `bvid` 至少一个非空 |
| `title` | `string = ""` | 最长 300 字符 |
| `cover` | `string = ""` | 最长 2048 字符 |
| `author` | `string = ""` | 最长 300 字符 |
| `pubdate` | `integer or null` | 0–9999999999 |
| `duration` | `string = ""` | 最长 32 字符 |
| `play` | `integer or null` | 非负 |
| `preferred_quality` | `string = ""` | 最长 120 字符 |

普通用户请求进入队列前，服务端固定写入 `destination="device"`、`group_id=""`、`group=""`、`force=false`、`owner_user_id=<当前会话用户>`、`min_height=<当前全局默认门槛>`，并把请求及项目中的 `preferred_quality` 清空为自动最高。

作品发现入口与权限：

| 方法与路径 | 角色 | 查询字段与结果 |
| --- | --- | --- |
| `GET /api/search` | 管理员 | `q`、`order=totalrank|click|pubdate`、`page`、`fresh`、`destination=library|device`；返回一个关键词结果页 |
| `GET /api/bilibili/creators/search` | 管理员 | `q`、`page`、`fresh`；返回一个 UP 主名称候选页 |
| `GET /api/bilibili/creators/resolve` | 管理员、普通用户 | `locator`、`order=pubdate|click`、`destination`、`fresh`；普通用户目标强制为 `device`，返回资料及第一页投稿 |
| `GET /api/bilibili/creators/{uid}/submissions` | 管理员、普通用户 | `order=pubdate|click`、`page`、`destination`、`fresh`；普通用户目标强制为 `device` |
| `POST /api/download/selection` | 管理员、普通用户 | 请求体复用 `DownloadRequest`；整批全部创建或零创建 |
| `POST /api/bilibili/creator-imports` | 管理员 | 请求体为 `uid`、`group_id`、`min_height`；目标固定为媒体库，返回 `data.job` 与是否新建的 `data.created` |
| `GET /api/bilibili/creator-imports` | 管理员 | 返回本次服务运行期作业数组 `data.items`，最新创建在前 |
| `GET /api/bilibili/creator-imports/{job_id}` | 管理员 | 返回单个运行期作业 |
| `POST /api/bilibili/creator-imports/{job_id}/cancel` | 管理员 | 停止后续发现和入队，不取消已创建下载任务 |
| `POST /api/bilibili/creator-imports/{job_id}/resume` | 管理员 | 仅分页失败作业可从 `failed_page` 继续 |
| `POST /api/bilibili/creator-imports/{job_id}/retry-failed` | 管理员 | 仅部分完成作业可重试本次运行期的单条失败项 |

`locator` 只接受正整数 UID，或 scheme 为 `https`、hostname 精确为 `space.bilibili.com`、不含 userinfo、端口为空或 `443` 且首个路径段为 UID 的主页 URL；尾随路径、查询和片段忽略，结果规范化为无前导零十进制字符串。

UP 主资料字段为 `uid`、`name`、`avatar`、`bio`、`followers`、`submission_count`、`profile_url`。投稿原始字段为 `bvid`、`title`、`author`、`cover`、`play`、`duration`、`duration_seconds`、`pubdate`、`url`；页根包含 `page`、`pages`、`total`、`page_size=20`、`order`、`cached`、`destination` 与 `limits`。`limits` 包含 `page_size`、`auto_scan_pages`、`selection`、`active_tasks`。Bilibili 图片的 `//` 与 `http://` 输入规范化为 `https://`，不受信协议或主机仍由路由层清空。

投稿装饰公共字段包含 `local_status`、`local_status_label`、`task_id`、`downloaded_at`、`selectable`、`block_reason`。管理员还可得到 `output_path`、`local_group`、`local_quality`、`tags`、`deleted_record`、`deleted_at`；普通用户响应不得出现这些管理员字段。安全错误码包括 `invalid_creator_locator`、`invalid_creator_query`、`creator_not_found`、`creator_no_public_videos`、`creator_inaccessible`、`bilibili_login_required`、`bilibili_risk_control`、`bilibili_unavailable`。

严格批量失败使用 `batch_conflict`、`active_task_limit` 或 `batch_create_failed`；可操作冲突放在 `data.items[]`，单项至少包含 `source_key`、`code`、`message`，可增加 `bvid`。整批失败时不创建任务记录、导出记录或内存任务。

全量入库开始请求拒绝额外字段；`uid` 复用 UP 主定位规则，`group_id` 允许空字符串以选择默认分组，`min_height` 可为允许的清晰度整数或 `null`。作业字段如下：

| 字段 | 类型与规则 |
| --- | --- |
| `id`、`uid`、`owner_user_id` | 非空字符串；拥有者只由认证会话注入 |
| `group_id`、`group_name` | 创建时解析并冻结的媒体库分组 |
| `min_height` | 允许的最低清晰度整数 |
| `cutoff_at`、`created_at`、`updated_at` | Unix 秒；`started_at`、`finished_at` 可为 `null` |
| `status` | `waiting`、`discovering`、`enqueuing`、`stopping`、`completed`、`partial`、`failed`、`cancelled` |
| `phase` | 当前阶段字符串，通常与状态一致 |
| `current_page`、`total_pages`、`total_estimate`、`pages_scanned` | 非负整数；总数为上游估计，不替代稳定遍历结果 |
| `discovered`、`processed`、`queued` | 非负整数；`processed` 为已入队、三类跳过和当前失败项之和 |
| `skipped_downloaded`、`skipped_active`、`skipped_deleted` | 三类预期跳过计数 |
| `failed_count`、`failures` | 单条失败数量和最多 100 条安全摘要；摘要只含 `bvid`、`title`、`message` |
| `last_error`、`failure_code`、`failed_page` | 分页或作业级安全失败；无失败页时为 `null` |
| `wait_position`、`retry_round`、`stability_pass` | 等待位置与本运行期重试/稳定遍历轮次 |
| `can_cancel`、`can_resume`、`can_retry_failed` | 服务端按当前状态计算的操作能力布尔值 |

作业仅驻留内存，不是 SQLite 字段；服务重启后列表为空。同一 UID 若已有活动或等待作业，开始请求返回该作业且 `created=false`。不存在作业返回 `creator_import_not_found`，非法状态转换返回 `creator_import_state_conflict`；UID、分组或清晰度在服务层校验失败时返回 `invalid_creator_import`，请求体字段缺失或类型不符时沿用 FastAPI 的 `422` 校验响应。

## 8. 账号与会话字段

账号字段：

| 字段 | 类型与规则 | 所有权 |
| --- | --- | --- |
| `id` | 非空字符串 | 服务端生成，不接受客户端指定 |
| `username` | 3–32 位 ASCII；字母开头；后续 `[A-Za-z0-9._-]`；NOCASE 唯一 | 创建后稳定 |
| `display_name` | 2–12 个汉字，可重复 | 本人或管理员可修改 |
| `role` | `admin` 或 `user` | 只由服务端设置；只允许一个启用管理员 |
| `password_hash` | scrypt 编码字符串 | 仅 SQLite；不进入 API |
| `disabled` | SQLite integer boolean，默认 `0` | 管理员管理；当前管理员不能禁用 |
| `must_change_password` | SQLite integer boolean，默认 `0` | 临时管理员/临时密码设为 `1`，成功改密清零 |
| `created_by` | string or null | 服务端记录创建来源 |
| `last_login_at` | Unix 秒或 null | 成功登录更新 |

正式密码为 10–64 位可见 ASCII，至少一个英文字母和一个数字，不含空格、中文或控制字符。登录请求为兼容旧客户端允许更宽输入，但认证成功仍以正式规则生成的密码为准。

会话字段：

| 字段 | 类型与规则 |
| --- | --- |
| `id` | 服务端生成的会话 ID |
| `user_id` | 非空用户外键；用户删除时级联会话 |
| `token_hash` | 明文高熵 Token 的 SHA-256；唯一；明文不持久化 |
| `csrf_token` | 每会话独立明文随机值，只返回当前已认证浏览器 |
| `created_at` | Unix 秒 |
| `expires_at` | 创建时间加 30 天 |
| `last_seen_at` | Unix 秒；最多每 60 秒持久化一次 |
| `user_agent` | 字符串，最多保存 300 字符 |
| `remote_addr` | 字符串，最多保存 100 字符 |
| `revoked_at` | Unix 秒或 null；非空表示撤销 |
| `revoke_reason` | 字符串，默认空 |

有效会话要求用户未禁用、`revoked_at is null` 且 `expires_at` 大于当前时间。淘汰顺序为 `last_seen_at ASC, created_at ASC, id ASC`。

## 9. 任务与导出字段

`task_records` 的跨边界字段：

| 字段 | 类型与规则 |
| --- | --- |
| `id` | 主键；重试继续使用原 ID |
| `owner_user_id` | 非空用户外键；只来自认证上下文 |
| `destination` | `library` 或 `device` |
| `source_key` | 规范化作品/源标识，默认空字符串 |
| `bvid` | 可为空的 BV 标识 |
| `title` | 显示标题，默认空字符串 |
| `status` | 任务状态；终态集合为 `success`、`skipped`、`failed`、`cancelled` |
| `created_at` | 必填 Unix 秒 |
| `started_at` | Unix 秒或 null |
| `finished_at` | Unix 秒或 null |
| `updated_at` | 必填 Unix 秒 |
| `payload_json` | UTF-8 JSON 快照；兼容扩展字段的承载区 |

`status`、`phase` 与时间字段遵循以下组合；不得只依据停止事件已经设置就提前写终态：

| 场景 | `status` | `phase` | `finished_at` |
| --- | --- | --- | --- |
| 排队 | `queued` | `queued` | `null` |
| 正常执行 | `running` | 当前执行阶段 | `null` |
| 已接受暂停 | `running` | `pausing` | `null` |
| 已接受取消 | `running` | `cancelling` | `null` |
| 已确认暂停 | `cancelled` | `paused` | Unix 秒 |
| 已确认取消 | `cancelled` | `cancelled` | Unix 秒 |
| 成功 | `success` | `completed` | Unix 秒 |
| 跳过或失败 | `skipped` 或 `failed` | 对应终态阶段 | Unix 秒 |

`phase_label` 对 `pausing`、`cancelling`、`paused` 分别为“正在暂停”“正在取消”“已暂停”。新快照以 `phase=paused` 判断暂停；历史 `status=cancelled` 快照只有在既有错误或进度文案明确包含“已暂停”时才按暂停兼容。运行中同意图停止和真正 `cancelled/cancelled` 终态的重复取消返回成功；成功、失败、跳过或暂停终态拒绝取消。`pausing` 可以升级为 `cancelling`，反向转换无效。所有终态均可原 ID 重试；重试保留 `owner_user_id` 和最初 `created_at`，清空上次的执行状态、结果、文件列表与日志，不保存尝试历史。

任务列表过滤字段为 `owner_user_id`、`status`、`destination`、`q`、`sort`、`direction`、`group_by_user`；`direction` 只允许 `asc` 或 `desc`。不提供 `keyword`、`sort_by`、`sort_dir` 别名。普通用户提交的 `owner_user_id` 被忽略并强制为本人；管理员可以省略拥有者查看全部用户。

`GET /api/events` 的 `view` 只允许 `full` 或 `summary`，默认 `full`：

| `view` | `tasks` | `summary` | `at` |
| --- | --- | --- | --- |
| `full` | 完整任务数组 | 状态计数对象 | 事件生成 Unix 秒 |
| `summary` | 不存在 | 状态计数对象 | 事件生成 Unix 秒 |

两种视图都使用 `event: tasks`；无任务变化时只按心跳规则发送 SSE 注释，不重复发送等价 JSON。普通用户摘要固定按本人过滤，管理员可省略拥有者查看全局计数。

设备导出字段至少包含 `task_id`、`owner_user_id`、`source_key`、`title`、`state`、`relative_path`、`filename`、`size`、`created_at`、`expires_at`、`downloaded_at`、`error`、`task_payload_json` 和 `cleanup_target_state`。有效同源导出的唯一判定域是 `owner_user_id + source_key`，状态限于仍有效的 `preparing` 或 `ready`，且 `expires_at` 尚未到期。`cleanup_target_state` 默认为空；`state=cleanup_pending` 时取 `downloaded`、`discarded` 或 `expired`，清理成功后进入该目标并清空。

`device_download_history` 的主键为 `owner_user_id + source_key`；`owner_user_id` 是 `users.id` 外键并在用户删除时级联，`downloaded_at` 是最近一次已证明完整领取的 Unix 秒。该表只记录角色为 `user` 的网站用户，不因任务或导出历史清理而删除。

## 10. Cookie、CSRF 与秘密字段

- HTTP 会话 Cookie 名为 `bili_session`；HTTPS 名为 `__Host-bili_session`，并设置 Secure。两者均为 HttpOnly、`SameSite=Lax`、`Path=/`。
- POST、PUT、PATCH 和 DELETE 使用请求头 `X-CSRF-Token`；值必须属于当前会话。
- `BILI_BOOTSTRAP_TOKEN`、`config/bootstrap-token.txt`、`BBDown.data`、完整 Bilibili Cookie、会话明文 Token 和密码均为秘密字段，不进入 Git、API 普通响应、SQLite 明文字段、日志或短期验证产物。

## 11. 迁移与兼容规则

- 配置合并只补缺失字段，不覆盖已有值、自定义字段或显式假值；JSON 原子写入并保留 `.bak`。
- SQLite schema 升级前创建 `userdata/backups/bili_workspace-v<旧版本>-YYYYMMDD-HHMMSS.db`，只保留最近 3 份。
- 旧任务和设备导出升级到 schema v4 时归属原管理员；没有有效管理员的旧库由迁移事务创建受限临时管理员以承接历史对象。
- v3→v4 不再次撤销已经迁移的有效会话。
- v4→v5 为 `exports` 增加 `cleanup_target_state` 并新增 `device_download_history`；只回填普通用户、非空 `source_key`、`state=downloaded` 且 `downloaded_at` 非空的记录，同一用户同一作品取最新时间。旧的无目标 `cleanup_pending` 映射为 `discarded`，不回填领取事实。
- 未来 schema 数据库不能被旧代码静默降级；跨 schema 回滚必须同时恢复匹配备份。
- Docker 模板把 `BUILD_LOCAL` 改为 `true` 只影响新生成的 `.env`；既有 `BUILD_LOCAL=false` 和既有 `BILI_IMAGE` 按配置保留规则不自动改写。
