# 需求文档

本文件是当前已交付、用户可观察且可验收行为及支持边界的唯一长期真源。实现结构见[设计文档](设计文档.md)，字段名称、默认值和兼容规则见[字段契约](字段契约.md)；未实现事项只进入[已知问题与待做需求](已知问题与待做需求.md)。

## 1. 产品定位与支持范围

`bili_workspace` 是面向私人使用的 Bilibili 搜索、下载、任务管理和媒体库网站，支持 Windows 本机单文件启动器以及 QNAP/NAS Docker 部署，并适配手机、平板和桌面浏览器。用户只能下载、保存和播放自己有权使用的内容，并应遵守适用法律、平台规则与版权要求。

当前能力包括搜索、下载、画质预览、任务控制、媒体库、分组、标签、在线播放、当前设备导出、网站账号、Bilibili 扫码登录和基础运维。当前不提供开放注册、匿名公网分享、多管理员、多节点调度、自动为全部媒体生成多码率 HLS、自动删除原始媒体或 Plex/Jellyfin 深度集成。

## 2. 网站账号、权限与登录设备

- 系统只允许一个启用的管理员；管理员可以创建和管理多个普通用户。
- 所有运行模式都要求网站账号登录。Windows 回环地址上的全新安装提供受限临时管理员 `admin / 123456`，只能从 `127.0.0.1` 或 `::1` 首次登录，并在修改密码前拒绝其他业务操作和非回环监听。
- Docker、NAS 和其他非回环全新部署使用一次性初始化令牌，不开放远程默认密码。
- 登录账号为 3–32 位 ASCII，必须以英文字母开头，后续只允许字母、数字、点、下划线和短横线；比较时不区分大小写。中文显示名为 2–12 个汉字，可重复。
- 正式密码为 10–64 位可见 ASCII，至少包含一个英文字母和一个数字，不允许空格、中文或控制字符。
- 每次登录形成独立设备会话；每用户最多 10 个有效会话。用户可以查看自己的有效设备、撤销其他单个设备、退出其他设备或只退出当前设备。
- 修改密码会保留并轮换当前设备会话，同时撤销该用户其他会话；管理员重置密码、禁用用户或主动撤销会话时，该用户现有会话立即失效。
- 所有已登录用户都能在用户菜单查看显示名、账号和角色，并修改显示名、修改密码、管理登录设备或退出。
- 普通用户只可使用下载、本人任务、本人日志、本人实时事件和本人设备导出；搜索、作品库、分组、标签、Bilibili 账号、系统设置和管理员 API 均拒绝访问。前端隐藏入口不能替代后端权限检查。
- 管理员可以创建普通用户、修改显示名、禁用或启用用户、设置临时密码、撤销全部会话，并查看该用户任务；不能创建第二个管理员，也不能禁用当前管理员。

## 3. Bilibili 作品发现

- 管理员搜索页提供“视频关键词”和“指定 UP 主”两种模式；UP 主模式既可按名称取得候选，也可输入精确正整数 UID 或 `https://space.bilibili.com/<UID>` 主页。名称候选不自动确认重名身份。
- 普通用户不开放搜索页和 UP 主名称搜索，只能在下载页输入精确 UID 或规范 HTTPS 主页；短链、跳转链接、HTTP、伪造主机、用户信息、非默认端口和名称均拒绝。定位不建立 UP 主白名单。
- UP 主浏览只读取公开视频投稿，不包含动态、专栏、音频、直播或收藏夹；每页固定 20 条，排序只提供“最新发布”和“播放最多”，多分 P 仍以整个 BV 为一个作品。
- 视频关键词模式提交 Bilibili 关键词、Bilibili 排序和页码；“不筛选”显示当前页原始结果，“精准”要求标题包含全部拆分词，“模糊”要求标题包含任意拆分词。标题筛选不匹配 UP 主名称或 BV，也不会在输入时访问网络。
- 默认隐藏已下载作品，管理员同时默认隐藏已删除作品。当前页没有可下载候选且仍有后页时，浏览器按页顺序继续读取，找到候选、到达末页、用户停止、发生失败或本轮累计 10 页时停止；不推测性预载，不合并多个页面。到达上限可从下一页继续，失败可从原页重试。
- 标题筛选使当前页变空时，只有用户点击“查找后续匹配”或在标题框按 Enter 才继续联网。摘要必须展示当前页以及本轮实际检查区间，不能暗示已经抓取全部投稿。
- 服务端原始页缓存按读取模式、关键词或 UID、排序、页码和 Bilibili Cookie 指纹隔离；浏览器按发现上下文、排序、页码和下载目标在当前网站会话内最多保留 24 页，切换账号或退出登录必须清空。
- 每条结果显示标题、BV、UP 主、封面、时长、播放量和发布信息。管理员状态来自当前目标队列、共享媒体库与删除历史；普通用户只接收本人活动任务、待领取导出和设备下载记录，不接收标签、媒体库路径、他人状态或删除历史。
- Bilibili 返回的协议相对图片地址和 `http://` 图片地址先统一为 HTTPS，再经过受信图片域名校验与浏览器加载失败回退；UP 主资料、视频关键词和投稿封面使用同一规则。
- 排队中、下载中和待领取作品不可选择；已下载或已删除作品关闭默认隐藏后可确认重下；失败、取消、过期和无本地记录的作品可重新选择。
- 翻页、排序和标题筛选保留跨页 BV 选择；更换关键词、UP 主或发现模式时先站内确认再清空。管理员最多选择 100 个作品，普通用户上限为 `10 - 本人当前活动任务数`，服务端提交时重新计算。
- 搜索和投稿卡统一使用严格批量创建：任一活动重复、待领取、媒体库冲突、配额、队列容量或持久化失败时创建零任务并返回逐项安全原因；创建成功后仍停留在当前页面。
- 管理员在 UP 主浏览且目标为媒体库时可以确认发起“UP 主全量入库”。作业以发起时间为截止点，忽略当前标题筛选和页面排序，固定按发布时间倒序遍历该 UID 的全部公开视频；普通用户和设备导出不提供该能力。
- 同一时间只执行一个全量入库作业，不同 UID 按发起顺序等待，相同 UID 的活动或等待请求幂等返回现有作业。作业只在当前服务运行期存在，重启后由管理员重新发起，不形成未来投稿订阅。
- 全量入库在入队前重新检查媒体库、活动任务和删除历史并分别跳过；既有失败或取消任务不阻止新任务。作业增量创建低优先级单投稿任务，限制自身活动窗口并为手工提交保留队列容量，不改变手工批量提交的 100 项原子合同。
- 取消全量入库只停止后续发现和入队，已经创建的下载任务继续执行。单条失败不影响其他投稿并可在本次运行期重试；分页有界重试仍失败时停在原页并可继续。作业完成表示投稿已入队或明确分类，不表示下载已经完成。

## 4. 下载与画质

- 下载前显示可用清晰度、分辨率、编码、帧率、分 P 和估算大小。
- 管理员可以选择最低清晰度或明确的单项目标档位；下载前预检和下载后实际码流复核必须同时通过。
- 任务不能在文件低于门槛或与指定档位不一致时静默显示成功。
- 下载目标包括永久保存到本机/NAS 媒体库，以及临时处理后导出到当前浏览器设备。
- 普通用户提交的下载始终由服务端收敛为当前设备导出，不得通过手工请求写入管理员媒体库、分组或强制覆盖；最低清晰度固定为管理员全局门槛，目标档位固定为空并自动选择当前 Bilibili 登录可用的最高档。
- 普通用户下载页保留彼此独立的“作品链接/编号”和“指定 UP 主”会话草稿，并在顶部集中提示本人待领取设备导出。
- 普通下载和搜索下载成功创建任务后只提示结果，不强制切换页面。
- 下载适配层必须保持可替换，避免产品能力与已经停止维护的单一第三方工具不可分离。

## 5. 任务中心与所有权

- 任务中心通过实时事件更新，并在网络异常后允许重新连接。
- 管理员任务中心单独展示本次运行期的全量入库作业、等待位置、遍历/入队进度、跳过分类和安全失败摘要；作业不伪装成普通下载任务，普通用户看不到该区域。
- 任务显示标题、BV、分组、目标、状态、阶段、时长和分 P；在底层输出可解析时显示真实百分比、当前大小、总大小、速度和 ETA。
- 支持单项和批量暂停、继续、取消、重试和删除，并可一键清理失败或已取消任务。
- 运行中暂停或取消被服务端接受后，任务继续计入活动任务并分别显示“正在暂停”或“正在取消”；只有执行步骤真实停止后才写入完成时间并进入“已暂停”或“已取消”。
- 同一运行中或已取消任务的取消请求可以安全重复；正在暂停但尚未停止的任务可以升级为取消，反向不能把正在取消降级为暂停。已经成功、失败、跳过或暂停的任务拒绝取消时，页面必须立即同步服务端最新状态。
- 成功、跳过、失败、取消和暂停终态均可重试；重试复用原任务 ID、拥有者和最初创建时间，清空上次执行状态、结果与日志，只保留最新一次执行。重试时可以修改最低清晰度或目标画质。
- 暂停后继续复用任务记录，但不承诺未经验证的字节级断点续传。
- 任务日志保留诊断信息并对敏感字段脱敏。
- 每个任务的拥有者只来自当前认证会话。管理员重试普通用户任务时，任务仍归原用户；普通用户访问他人任务或导出时按对象不存在处理。
- 普通用户最多同时拥有 10 个排队或运行任务；终态任务保留 7 天且最多 100 条。管理员终态任务最多 500 条，不应用普通用户的 7 天规则。
- 活动任务、正在取消的任务，以及仍在准备、可下载或等待清理的导出不参与历史清理。
- 管理员可以按用户、状态、目标、关键词、创建时间和完成时间查询、排序及分组任务；筛选和排序由服务端数据库执行。
- 普通用户任务页只显示本人任务和设备导出，不提供用户或媒体库目标筛选；管理员任务卡显示“显示名（username）”。

## 6. 分组、标签与删除历史

- 下载时可以选择已有分组，也可以在下载表单内创建并选中新分组。
- 独立分组页显示作品数量、占用空间、任务和最近更新，并支持重命名、合并、移动作品、批量移动和删除空分组。
- 作品卡片和播放详情均可修改分组；显示名称与物理目录标识分离，普通重命名不搬动大型文件。
- 删除分组不能隐式删除媒体文件。
- 标签定义来自配置模板，标签关系保存在 SQLite，不依赖扫描媒体文件。
- 搜索结果和作品库作品都可以打标签；作品库支持标签、分组和“无标签”筛选。用户自定义颜色优先于默认配色。
- 删除作品时，作品库记录和媒体文件按用户选择处理；只有所选文件操作、作品库记录、标签和删除历史全部完成才报告该作品成功，失败项保留可重试状态。批量删除逐作品提交并逐项报告成功或失败，不承诺整批原子回滚；删除历史使用独立记录，不使用普通标签代替。
- 删除历史不在作品库显示，但搜索结果可以标记“已删除”；主动重新下载成功后可以清除相应删除历史并恢复为“已下载”。

## 7. 媒体库、播放与设备导出

- 作品库使用服务端筛选、分页和排序，支持关键词、分组、标签、无标签、编码、清晰度和观看状态。
- 概览页最近作品卡可通过鼠标、Enter 或 Space 进入作品库并直接打开对应作品详情；详情按媒体 ID 读取，不依赖作品是否位于作品库当前筛选页。
- 排序支持下载时间、最近观看、标题、时长、文件大小、分组和标签的升降序。
- 支持跨页选择、批量标签、下载、删除、修改分组，以及多文件和多分 P 播放。
- 作品库重复进入同一筛选页时可以先显示当前会话内最近成功结果并在后台刷新；刷新失败时保留旧内容、明确提示数据可能已过期并提供重试。勾选作品和修改单项标签不应重建当前页全部作品卡片。
- 播放支持 `HEAD`、字节 `Range`、`206`、`416`、`ETag`、拖动、断点续播、最近观看，并避免把整个大文件一次性读入内存。
- 默认优先播放原始文件；浏览器不兼容时由用户手动生成 H.264/AAC MP4 兼容副本，兼容副本不能覆盖原始高质量文件。
- 作品封面应完整显示，不能无提示裁掉主体。
- 设备导出先在服务器完成临时下载、混流和必要打包，再使用流式响应发送到当前设备。
- 服务器完整发送全部响应字节后立即删除专属临时文件；浏览器中断、断网或未读完时保留到可配置 TTL，允许重试。
- 浏览器只能通过数据库对象 ID 访问导出，不能提交任意服务器路径；清理只能作用于设备导出专属临时目录，不能触碰媒体库。
- 不同用户可以同时导出同一个作品，内部队列、索引和临时产物按用户隔离。
- 只有普通用户的浏览器完整消费无 Range 的 GET 导出响应才建立本人设备下载记录；HEAD、未读完、连接中断、任务成功或仅准备就绪均不建立。
- 完整发送先持久化领取时间与设备下载记录，再清理临时文件；清理失败进入带明确目标状态的可重试清理，不得丢失领取事实或在重试时改写第一次证明时间。
- 设备下载记录按 `owner_user_id + source_key` 独立保留，不随任务、日志或导出历史清理；删除网站用户时随用户级联删除。

## 8. 界面与交互

- 当前前端不使用浏览器原生 `prompt` 或 `confirm` 承担产品交互；修改显示名、设置临时密码、分组重命名和确认操作使用站内组件。
- 桌面端普通按钮、输入框和选择框为 40px，紧凑控件为 32px，主要操作按钮为 48px；手机和平板可触控控件不低于 44px。
- 用户、分组和任务拥有者等动态选项超过 8 项时使用可搜索的两列选择列表；固定少量选项以及不足 9 项的动态数据使用普通选择框。
- 管理员用户管理在桌面使用表格、手机使用卡片；五档固定视口不应出现横向滚动或可见控件重叠。
- 管理员账号区区分“Bilibili 登录”和“网站账号与设备”；前者只承接扫码、Cookie 和登录状态，后者承接用户名、显示名、密码和设备会话。
- 设置页默认展示监听地址、端口、媒体目录、默认分组和默认最低清晰度；任务超时、轮询后备间隔、画质和编码优先级位于高级折叠区。折叠内容关闭时不参与布局。
- 概览、作品库、分组和账号页可以先呈现当前网站会话内最近成功数据并后台刷新；旧数据不能伪装成最新结果，刷新失败必须显示降级提示和重试入口。退出登录或会话失效后不得向下一账号复用这些数据。
- 只有概览页和任务页需要任务实时连接：概览只接收计数摘要，任务页接收完整任务；切到其他页面或退出登录后不保留任务事件连接。

## 9. 网络、部署与持久化

- 监听地址支持 `127.0.0.1`、`0.0.0.0`、指定局域网 IP、IPv6 和合法主机名；端口范围为 1–65535，并提示 3389 可能与 Windows 远程桌面冲突。
- 设置页展示可用于手机访问的局域网地址，多网卡时列出多个候选地址；代理环境应提示将局域网网段和应用地址设为直连。
- 公网部署推荐使用独立 HTTPS 子域名和受信任反向代理，只开放 443；转发头只信任明确配置的代理来源 IP。
- Windows 必须由用户选择仓库外数据根并在其中持久化 `config/`、`userdata/` 和 `downloads/`；Docker 模式固定映射 `/data/config`、`/data/userdata` 和 `/downloads`。删除 EXE 同级 `launcher.json` 后可重新选择原数据根，更新源码、重新构建镜像或重建容器不能清空这些目录。
- Git 只跟踪配置模板；启动和更新补充缺失字段，但保留现有值、自定义字段、空字符串、`0`、`false` 和用户选择。损坏配置不能被模板静默覆盖。
- SQLite 迁移前创建一致性备份，只保留最近 3 份；迁移失败时不开放 HTTP 服务。涉及 schema 回滚时必须同时恢复匹配备份，不能只回退代码。
- Docker 容器以非 root、非 privileged、只读根文件系统运行，不挂载 Docker socket，并具备健康检查、日志轮转和优雅停止。

## 10. 源码更新与交付边界

- GitHub `main` 直接保存可审查源码树，不使用 Base64 分片或 Actions 自解包恢复源码。
- 项目停止未来正式发布：源码 push 和普通 CI 不创建新 tag、GitHub Release，也不推送或更新 GHCR 正式镜像。
