# 需求文档

本文件是当前已交付、用户可观察且可验收行为及支持边界的唯一长期真源。实现结构见[设计文档](设计文档.md)，字段名称、默认值和兼容规则见[字段契约](字段契约.md)；未实现事项只进入[已知问题与待做需求](已知问题与待做需求.md)。

## 1. 产品定位与支持范围

`bili_workspace` 是面向私人使用的 Bilibili 搜索、下载、任务管理和媒体库网站，支持 Windows 本机、源码运行以及 QNAP/NAS Docker 部署，并适配手机、平板和桌面浏览器。用户只能下载、保存和播放自己有权使用的内容，并应遵守适用法律、平台规则与版权要求。

当前能力包括搜索、下载、画质预览、任务控制、媒体库、分组、标签、在线播放、当前设备导出、网站账号、Bilibili 扫码登录和基础运维。当前不提供开放注册、匿名公网分享、多管理员、多节点调度、自动为全部媒体生成多码率 HLS、自动删除原始媒体或 Plex/Jellyfin 深度集成。

## 2. 网站账号、权限与登录设备

- 系统只允许一个启用的管理员；管理员可以创建和管理多个普通用户。
- 所有运行模式都要求网站账号登录。Windows 回环地址上的全新安装提供受限临时管理员 `admin / 123456`，只能从 `127.0.0.1` 或 `::1` 首次登录，并在修改密码前拒绝其他业务操作和非回环监听。
- Docker、NAS 和其他非回环全新部署使用一次性初始化令牌，不开放远程默认密码。
- 登录账号为 3–32 位 ASCII，必须以英文字母开头，后续只允许字母、数字、点、下划线和短横线；比较时不区分大小写。中文显示名为 2–12 个汉字，可重复。
- 正式密码为 10–64 位可见 ASCII，至少包含一个英文字母和一个数字，不允许空格、中文或控制字符。
- 每次登录形成独立设备会话；每用户最多 10 个有效会话。用户可以查看自己的有效设备、撤销其他单个设备、退出其他设备或只退出当前设备。
- 修改密码会保留并轮换当前设备会话，同时撤销该用户其他会话；管理员重置密码、禁用用户或主动撤销会话时，该用户现有会话立即失效。
- 所有已登录用户都能在用户菜单查看显示名、账号和角色，并修改显示名、修改密码、管理登录设备或退出。
- 普通用户只可使用下载、本人任务、本人日志、本人实时事件和本人设备导出；搜索、作品库、分组、标签、Bilibili 账号、系统设置和管理员 API 均拒绝访问。前端隐藏入口不能替代后端权限检查。
- 管理员可以创建普通用户、修改显示名、禁用或启用用户、设置临时密码、撤销全部会话，并查看该用户任务；不能创建第二个管理员，也不能禁用当前管理员。

## 3. Bilibili 搜索

- 搜索区只提交 Bilibili 关键词、Bilibili 排序和页码；每次只加载当前页，每页固定 20 条。
- “不筛选”显示当前页原始结果；“精准”保留标题包含全部拆分词的作品；“模糊”保留标题包含任意拆分词的作品。
- 精准和模糊只匹配标题；UP 主名称或 BV 号不能让标题不匹配的作品通过。
- 切换二级筛选模式或修改标题筛选词不访问网络。
- 当前页成功显示后，浏览器空闲时最多预加载下一页一页；省流量模式、当前页失败或查询已变化时不预加载，且永不预加载第三页或连续扫描多页。
- 页码只用于导航，不表示对应页面已经抓取；只有“刷新 B站结果”会清除缓存并重新请求当前页。
- 修改关键词、Bilibili 排序或路由后，旧请求和旧响应不得覆盖当前结果。
- 每条结果显示标题、BV、UP 主、封面、时长、播放量和发布信息，并在同一响应中标记标签及未下载、排队中、下载中、已下载、失败、已取消或已删除状态。
- 默认提供“屏蔽已下载和已删除”，并支持原作品页直达、跨页选择、批量标签、画质预览和批量下载。
- 创建下载任务后停留在当前搜索页和页码，不强制跳转任务中心。
- 摘要分别显示 Bilibili 当前页原始数量和标题筛选后数量，不能暗示已扫描全部页面。

## 4. 下载与画质

- 下载前显示可用清晰度、分辨率、编码、帧率、分 P 和估算大小。
- 用户可以选择最低清晰度或明确的目标档位；下载前预检和下载后实际码流复核必须同时通过。
- 任务不能在文件低于门槛或与指定档位不一致时静默显示成功。
- 下载目标包括永久保存到本机/NAS 媒体库，以及临时处理后导出到当前浏览器设备。
- 普通用户提交的下载始终由服务端收敛为当前设备导出，不得通过手工请求写入管理员媒体库、分组或强制覆盖。
- 普通下载和搜索下载成功创建任务后只提示结果，不强制切换页面。
- 下载适配层必须保持可替换，避免产品能力与已经停止维护的单一第三方工具不可分离。

## 5. 任务中心与所有权

- 任务中心通过实时事件更新，并在网络异常后允许重新连接。
- 任务显示标题、BV、分组、目标、状态、阶段、时长和分 P；在底层输出可解析时显示真实百分比、当前大小、总大小、速度和 ETA。
- 支持单项和批量暂停、继续、取消、重试和删除，并可一键清理失败或已取消任务。
- 失败任务可以修改最低清晰度或目标画质后重试；重试复用原任务 ID，不新增重复任务记录。
- 暂停后继续复用任务记录，但不承诺未经验证的字节级断点续传。
- 任务日志保留诊断信息并对敏感字段脱敏。
- 每个任务的拥有者只来自当前认证会话。管理员重试普通用户任务时，任务仍归原用户；普通用户访问他人任务或导出时按对象不存在处理。
- 普通用户最多同时拥有 10 个排队或运行任务；终态任务保留 7 天且最多 100 条。管理员终态任务最多 500 条，不应用普通用户的 7 天规则。
- 活动任务、正在取消的任务，以及仍在准备、可下载或等待清理的导出不参与历史清理。
- 管理员可以按用户、状态、目标、关键词、创建时间和完成时间查询、排序及分组任务；筛选和排序由服务端数据库执行。
- 普通用户任务页只显示本人任务和设备导出，不提供用户或媒体库目标筛选；管理员任务卡显示“显示名（username）”。

## 6. 分组、标签与删除历史

- 下载时可以选择已有分组，也可以在下载表单内创建并选中新分组。
- 独立分组页显示作品数量、占用空间、任务和最近更新，并支持重命名、合并、移动作品、批量移动和删除空分组。
- 作品卡片和播放详情均可修改分组；显示名称与物理目录标识分离，普通重命名不搬动大型文件。
- 删除分组不能隐式删除媒体文件。
- 标签定义来自配置模板，标签关系保存在 SQLite，不依赖扫描媒体文件。
- 搜索结果和作品库作品都可以打标签；作品库支持标签、分组和“无标签”筛选。用户自定义颜色优先于默认配色。
- 删除作品时，作品库记录和媒体文件按用户选择处理；删除历史使用独立记录，不使用普通标签代替。
- 删除历史不在作品库显示，但搜索结果可以标记“已删除”；主动重新下载成功后可以清除相应删除历史并恢复为“已下载”。

## 7. 媒体库、播放与设备导出

- 作品库使用服务端筛选、分页和排序，支持关键词、分组、标签、无标签、编码、清晰度和观看状态。
- 排序支持下载时间、最近观看、标题、时长、文件大小、分组和标签的升降序。
- 支持跨页选择、批量标签、下载、删除、修改分组，以及多文件和多分 P 播放。
- 播放支持 `HEAD`、字节 `Range`、`206`、`416`、`ETag`、拖动、断点续播、最近观看，并避免把整个大文件一次性读入内存。
- 默认优先播放原始文件；浏览器不兼容时由用户手动生成 H.264/AAC MP4 兼容副本，兼容副本不能覆盖原始高质量文件。
- 作品封面应完整显示，不能无提示裁掉主体。
- 设备导出先在服务器完成临时下载、混流和必要打包，再使用流式响应发送到当前设备。
- 服务器完整发送全部响应字节后立即删除专属临时文件；浏览器中断、断网或未读完时保留到可配置 TTL，允许重试。
- 浏览器只能通过数据库对象 ID 访问导出，不能提交任意服务器路径；清理只能作用于设备导出专属临时目录，不能触碰媒体库。
- 不同用户可以同时导出同一个作品，内部队列、索引和临时产物按用户隔离。

## 8. 界面与交互

- 当前前端不使用浏览器原生 `prompt` 或 `confirm` 承担产品交互；修改显示名、设置临时密码、分组重命名和确认操作使用站内组件。
- 桌面端普通按钮、输入框和选择框为 40px，紧凑控件为 32px，主要操作按钮为 48px；手机和平板可触控控件不低于 44px。
- 用户、分组和任务拥有者等动态选项超过 8 项时使用可搜索的两列选择列表；固定少量选项以及不足 9 项的动态数据使用普通选择框。
- 管理员用户管理在桌面使用表格、手机使用卡片；五档固定视口不应出现横向滚动或可见控件重叠。
- 管理员账号区区分“Bilibili 登录”和“网站账号与设备”；前者只承接扫码、Cookie 和登录状态，后者承接用户名、显示名、密码和设备会话。
- 设置页默认展示监听地址、端口、媒体目录、默认分组和默认最低清晰度；任务超时、轮询后备间隔、画质和编码优先级位于高级折叠区。折叠内容关闭时不参与布局。

## 9. 网络、部署与持久化

- 监听地址支持 `127.0.0.1`、`0.0.0.0`、指定局域网 IP、IPv6 和合法主机名；端口范围为 1–65535，并提示 3389 可能与 Windows 远程桌面冲突。
- 设置页展示可用于手机访问的局域网地址，多网卡时列出多个候选地址；代理环境应提示将局域网网段和应用地址设为直连。
- 公网部署推荐使用独立 HTTPS 子域名和受信任反向代理，只开放 443；转发头只信任明确配置的代理来源 IP。
- Windows/源码模式持久化 `config/`、`userdata/` 和 `downloads/`；Docker 模式固定映射 `/data/config`、`/data/userdata` 和 `/downloads`。更新源码、重新构建镜像或重建容器不能清空这些目录。
- Git 只跟踪配置模板；启动和更新补充缺失字段，但保留现有值、自定义字段、空字符串、`0`、`false` 和用户选择。损坏配置不能被模板静默覆盖。
- SQLite 迁移前创建一致性备份，只保留最近 3 份；迁移失败时不开放 HTTP 服务。涉及 schema 回滚时必须同时恢复匹配备份，不能只回退代码。
- Docker 容器以非 root、非 privileged、只读根文件系统运行，不挂载 Docker socket，并具备健康检查、日志轮转和优雅停止。

## 10. 源码更新与交付边界

- GitHub `main` 直接保存可审查源码树，不使用 Base64 分片或 Actions 自解包恢复源码。
- 项目停止未来正式发布：源码 push 和普通 CI 不创建新 tag、GitHub Release，也不推送或更新 GHCR 正式镜像。
- Windows 和源码用户从 `main` 更新；Docker 新部署默认从当前检出源码本地构建。既有 Docker 配置不会被覆盖，现有用户需要显式启用本地构建才能运行更新后的源码。
- 既有 V0.7.0 tag、GitHub Release 和 GHCR 镜像是冻结的历史后备，不代表后续源码状态。
- CI 和本地自检可以产生短期验证证据，但这些产物不是正式发布物。
