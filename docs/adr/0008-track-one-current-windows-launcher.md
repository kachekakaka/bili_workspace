# 仓库跟踪唯一的 Windows 打包快照

仓库在 `dist/` 中只跟踪一份由维护者明确触发、完成构建与自检后确认的 Windows 打包快照，使 Windows 使用和 Docker 导出不要求先安装 Python、Git 或重建 EXE。正式快照只能从构建前干净且已提交的 Git `HEAD` 生成，构建记录保存完整源码 commit；它可以落后于 `main`。普通源码变更和 CI 不强制更新或上传约 83 MiB 的 EXE。凡任务修改会被内嵌的应用、网页、Docker 上下文或启动器构建输入，完成前必须生成 Windows 候选构建并通过自检；候选允许验证尚未提交的工作树，但不替换 `dist`、不进入仓库且不上传。只有维护者明确决定晋升时，合格候选才能成对替换 EXE 与 `launcher/current-build.json`；其他 EXE 和中间产物不跟踪。该做法不恢复正式发布；若单文件超出普通 Git 托管边界，必须重新选择分发方式。
