# 真实 Bilibili 测试由凭据源单标记授权并先于影响域模拟测试

本地真实测试只在凭据源数据根含有用户明确创建的 `.bili-workspace-live-test.json` 时选择；该标记保存非秘密的测试 UID 与 8 个从该 UID 既有下载记录中选出的较短作品 BV 号，并只长期授权把指定 `BBDown.data` 复制进单次新建的隔离运行，执行器不得自行创建标记、修改凭据源或读取其余业务数据。执行时必须从真实投稿结果验证这 8 个 BV 均属于标记 UID；目标不可用或归属不符时记为 `blocked` 并要求维护者更新标记，不自动替换。隔离运行复用既有 `BILI_TEST_ROOT`、仓库外路径校验和逐次所有权标记，不另设第二套目录协议；Windows 真链测试必须显式指定 `BILI_TEST_ROOT`，不得回退到通常位于 `%LOCALAPPDATA%` 的系统临时目录。

选中后先做快速静态检查和真实只读成功链，下载、入库或播放链受影响时依次抽测标记中的作品：至少一个作品完整下载并入库成功才形成成功链证据，随后继续到 8 个或任一硬上限先到为止；每次运行仍以 15 分钟、2 GiB 数据增长和开始前 5 GiB 可用空间为硬上限，并记录实际完成数。随后运行影响域模拟测试；开发期测试当前源码，启动器变化再测候选 EXE，外部网络、登录或风控不足记为 `blocked`，产品合同不符记为 `failed`，完整项目自检保留给共享高风险变更及提交或推送前。

真实外部链路通过 UP 主解析和投稿分页取得资料、作品及封面，再把标记中的 8 个 BV 交给现有严格批量下载入口；它不启动会遍历并增量提交全部作品的全量入库作业。全量入库的调度、去重、容量等待、取消和恢复由影响域模拟测试证明。前端受影响时，浏览器在隔离产品页面验证概览作品入口、UP 主搜索、真实封面、跨页选择和批量下载，并只打开全量入库确认后取消；只有后端受影响时直接使用 HTTP API，不强制重复浏览器流程。

本套件首期只在 Windows 本地运行，可验证当前源码；启动器或资源变化时还验证受影响的候选 EXE。CI、Linux 和 macOS 不读取标记或真实凭据，也不执行本套件。每次运行在隔离目录保存脱敏 `summary.json`、允许保留的公开响应正文和进程日志；摘要记录源码或 EXE 身份、目标 BV、实际完成数、耗时、空间增长、最终状态和安全失败分类，不采集浏览器 HAR 或完整网络流量。

真链测试可以保存公开响应正文、下载结果和进程日志，但不得额外采集请求头、Cookie 值、登录二维码载荷或原始账号响应，也不得把凭据内容复制到日志或报告。成功运行退出前删除凭据副本，其他产物可以保留；失败运行允许连同原始凭据副本保留。创建满 3 天的自有运行目录只有在维护者明确指定后才能精确删除，不运行自动清理或定时任务。

允许保留的真实公开响应还用于自动生成模拟测试的清洗后完整结构候选：生成器保留全部非动态字段名、嵌套、类型、空值和集合形状，以固定占位值替换真实身份、内容和易变值，不由维护者手工裁剪成最小响应；若真实身份或内容本身被用作 JSON 字段名，则安全停止而不生成可写回候选。正常真测自动比较现有结构；只有检测到结构变化时才在隔离运行目录生成候选，避免每次运行都人工维护，也不修改仓库。只有维护者或其明确授权的 AI 显式执行 fixture 刷新后，候选才能写入仓库并接受 review 和模拟测试；刷新不包含提交或推送授权。

真实响应结构发生变化、但当前产品行为仍可判定正常时，本套件记为 `inconclusive` 并保存清洗候选，不能用警告状态宣称通过；完成 review、确认变化兼容并显式刷新 fixture 后，重新运行才能形成 `passed`。结构变化已经导致搜索、封面、下载或其他产品合同异常时直接记为 `failed`。
