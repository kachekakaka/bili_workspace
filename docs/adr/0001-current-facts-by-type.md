# 当前事实按事实类型承接

项目原有的专题汇编与标准核心文件同时声明长期职责，导致同一变化可能需要在多处同步。我们决定由 `docs/需求文档.md`、`docs/设计文档.md` 和 `docs/字段契约.md` 分别作为用户可观察行为、实现结构和字段规则的唯一当前真源；`docs/产品需求与架构基线.md`、`docs/账号权限与会话管理.md` 和 `docs/任务所有权与保留策略.md` 仅作为迁移期材料，在事实完成拆分并更新入口后作为 V0.6 历史专题归档。选择按事实类型承接，是为了让每项事实只有一个权威位置，并避免专题汇编与核心文档持续并列。

`docs/V0.6功能与验收.md`、`docs/V0.6.2_UI发布与验证.md`、`docs/UI_UX_REVIEW_v0.6.2.md` 和 `docs/UI_ISSUES.md` 同样在当前事实完成承接后归档；继续运行的 V0.6.2 命名测试或 workflow 只是兼容回归标识，不使这些版本材料继续承担当前文档职责。

`docs/V0.7功能与验收.md`、`docs/releases/V0.7.0.md` 和 `docs/需求落实清单.md` 是已完成发布的版本快照，也在当前事实承接后归档；“仍是最新版本”不延长其活动生命周期。移动 Release notes 前必须先更新或退出 workflow 对该路径的机械引用；当前版本事实由核心真源承接，版本历史由 `CHANGELOG.md` 和归档承接。
