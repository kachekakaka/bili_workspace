## 3. 共同根因与目标

### 3.1 授权仍按工具类别切割

当前 `AGENTS.md` 要求任何 Shell、Git、构建、测试或产品命令都另行授权，并声明修改授权不包含命令、验证和删除。新版标准骨架改为按实际副作用分类：

- 本地文件读取、搜索及不改变工作区、索引、引用或远端状态的 Git 查询属于默认允许的只读操作；
- 公开、无需认证、纯读取、不上传本地或非公开内容、不收费且不改变外部状态的联网读取默认允许；
- 用户明确授权按已确认方案实施时，可以同时覆盖确定范围内的文件新增、修改、重命名和方案列明删除、普通验证、结果记录、已列明普通下载，以及完成条件满足后的状态更新、方案归档、索引更新和精确任务清理；
- 验证升级、新增副作用、候选实质漂移或需要新语义决定时只申请授权差额；
- commit、push、PR、发布、安装、破坏工作区或改写历史的 Git 操作，以及认证或私有访问、上传、外部写入、付费或明显大规模联网、产品进程、真实数据、全量测试和正式认证仍须明确授权。

目标是让 `AGENTS.md` 成为上述长期授权语义的唯一入口，其他文档只引用或实例化任务值，不复制、放宽或重新切割规则。

### 3.2 收尾与关闭仍沿用旧停点

`docs/README.md` 当前规定普通实施任务必须在用户验收并另行授权关闭后，才能退出待办、归档方案和更新索引。新版标准骨架要求：保存方案不构成施工授权；但后续一次明确实施授权在完成条件和列明验收要求满足、没有授权差额时，可以覆盖生命周期关闭。只有方案明确要求用户验收、新的语义决定或高风险动作时才停下等待。

目标是更新项目级收尾模板说明，并保持方案关闭与 commit、push、PR 相互独立。完成条件不得预写成结果，中途门禁也不得替代关闭后的最终状态验证。

### 3.3 测试清理边界没有按所有权和方案范围分层

`SoftwareTesting/SAFETY.md` 当前把任何运行目录清理都要求用户再次明确提出。新版规则允许已确认方案列明的、本任务创建且所有权可验证的精确运行目录随实施授权清理；未列明、宽泛匹配、未解析路径、其他运行、测试根、仓库外非任务产物、所有权不明或涉及真实数据的删除仍须精确授权。

目标是只调整治理语义，不改变 T-PROJECT 的默认保留、安全标记、containment、真实数据和进程所有权契约。

### 3.4 入口职责偏宽

根 `README.md` 当前复制了较多需求、设计、持久化、运维和验证细节；`docs/README.md` 也直接保存当前版本、持久化路径和 Docker 行为。新版标准职责要求：

- 根入口只保留简介、当前能力简要边界、主要目录、最短使用入口、唯一构建与交付入口，以及文档和测试总入口；
- 文档索引只承接活动文档职责索引、事实分流、生命周期、收尾模板、条件模块和归档入口。

实施时必须先证明被压缩内容已经由需求、设计、字段契约或运维文档承接。无法证明时停止相应内容移动或删减，并形成内容一致性增量交接，不能为了缩短入口丢失当前事实。

### 3.5 与现行 T-PROJECT 方案共享规则和文件

`TEST-ENTRY-20260803` 方案仍处于“实施中”，并与本方案共享根入口、文档索引、测试安全和待办入口。该方案中的既往授权、实施和验证记录属于历史事实，不能因规则迁移重写；其中面向未来的授权、补证和关闭表述若与新长期规则直接冲突，应由其活动真源所有者在当前证据下做最小同步。

本方案只负责建立新长期结构规则并指出冲突位置，不把 T-PROJECT 的实现、测试结果或关闭决定并入自身完成证明。实施前若对方方案正在修改共享文件，停止共享路径并先完成联合只读复核。
