# TASKS-20260815：任务页性能优化方案

- 待办 ID：`TASKS-20260815`
- 状态：`已完成`
- 治理路线：用户报告运行缺陷后的记录与修复规划
- 保存决定：用户于 2026-08-15 明确要求“保存方案然后 review 一下”
- 当前阶段：用户于 2026-08-15 实施验收通过并授权关闭；活动待办已退出，方案与归档索引已经形成历史导航
- 主责边界：任务页进入卡顿与 SSE 后台持续负载的性能优化；不改变任务模型、API 协议字段或下载算法

## 1. 背景与证据

用户报告：任务页每次进入都很卡，且感觉后台有很大工作量。用户为管理员，任务记录为几十条量级（小于 100 条）。

### 1.1 根因证据

- 后端 SSE（`app/task_ownership_api.py:609-639`）：`/api/events` 循环每 1 秒执行一次全量 `_list_records`（SQLite 全量查询，limit 最高 5000，`task_ownership_store.py:359-403`）并对每条记录执行 `_live_record`/`_decorate_task`/`_compact_task`，随后 `json.dumps` 全量序列化计算 fingerprint——**即使没有任何变化，空闲时也每秒全量计算**。这是“后台很大工作量”的来源。
- 前端每次进入（`web/assets/app/pages/tasks-impl.mjs`）：`mount` 中 `context.taskStream.start()` 后 `await reload()`（:167-173、:420）全量拉取一次，SSE 首帧又推送全量一次，两次都触发 `renderResults()` 全量 `innerHTML` 重建（:164）。
- 前端 SSE 订阅（:410-414）：每次事件到达都执行 `viewState.data = snapshot.tasks` 并 `renderResults()`，下载运行时进度每秒变化 → 每秒全量重建全部任务卡片 DOM。几十条卡片每秒整树重建即为“进入/运行时卡顿”主因。
- 路由事实：`/api/events` 由 `task_ownership_router`（`main.py:261`）处理，`api.py` 的 legacy `api_events`（`api.py:1203-1246`）被遮蔽且未接线，不在本次改动范围。
- queue 变更通知现状（`app/queue.py:286-294`）：`_notify_locked` 只在存在 `on_state_change` 回调时调用回调，无独立变更计数；进度更新（:777、:885）与状态转换均经过 `_notify_locked`，可承载变更计数。

### 1.2 关联事实

- SSE 保持 1 秒轮询结构即可实现所需可观察行为：空闲零计算、变化才推送、进度每秒最多合并一次；无需跨线程事件桥。
- 任务量级为几十条，payload 全量传输（每次几十 KB）可接受，不做增量 payload 推送与虚拟滚动/分页。

## 2. 差异、选项与用户决定

### 2.1 处理方式

- 用户决定：记录 + 形成修复方案；与 BBDOWN-20260815 分开登记独立待办。

### 2.2 后端推送机制

- 选项 A：轮询 + 变更计数——`_notify_locked` 无条件递增变更计数（与持久化回调解耦）；SSE 循环检查计数变化，变了才全量查询与序列化，没变只发 keepalive；
- 选项 B：线程→asyncio 事件桥——queue 变更跨线程通知唤醒 SSE。
- 用户决定：选项 A。改动小、线程安全天然（计数在既有 RLock 内递增，读侧取整数值）、行为可控。

### 2.3 前端渲染机制

- 选项 A：差量渲染——SSE 事件按任务 id 对比，新增插入、变化重建单个卡片、消失移除，摘要文本更新；进入页面时 reload 与 SSE 首帧在差量机制下不再双重全量渲染；
- 选项 B：保持全量渲染，仅降低推送频率。
- 用户决定：选项 A（与后端选项 A 组合为方案 C）。分组模式（管理员按用户分组）保底全量渲染，该模式为低频切换。

### 2.4 验证边界

- 用户决定：普通验证只覆盖后端单测、ruff 与既有 pytest 回归；前端差量渲染依赖 Playwright（属 T-PROJECT full 浏览器阶段），需另行授权，普通验证不覆盖。

## 3. 实施范围（获得实施授权后执行）

### 3.1 文件清单与改动内容

| 文件 | 动作 | 内容 |
| --- | --- | --- |
| `app/queue.py` | 修改 | `_notify_locked` 无条件递增 `self._change_count`（与 `on_state_change` 回调解耦，RLock 内递增）；暴露只读 `change_count()` |
| `app/task_ownership_api.py` | 修改 | `/api/events` 循环：读取 library 与 export 两个队列的变更计数，与上次不同才执行 `_list_records` + fingerprint 计算与推送；无变化只按间隔发 keepalive；循环间隔保持 1 秒（进度天然合并） |
| `web/assets/app/pages/tasks-impl.mjs` | 修改 | `renderResults` 非分组模式差量渲染：按可见任务 id 与签名对比，新增/更新/移除卡片节点；摘要与选中清理逻辑保留；分组模式保持全量 |
| `tests/` | 修改/新增 | queue 变更计数用例（状态与进度更新递增、无回调时也递增）；SSE 空闲不查询/变化才推送用例（monkeypatch `_list_records` 计数断言） |
| `CHANGELOG.md` | 修改 | 未发布章节登记任务页性能优化 |

### 3.2 不做的事

- 不改 `api.py` legacy `/api/events`（未接线、被遮蔽）；
- 不做跨线程事件桥、增量 payload 推送、虚拟滚动/分页；
- 不改任务模型、API 协议字段、数据库 schema。
