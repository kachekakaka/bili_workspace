## 目标与范围

本方案治理项目约束、长期文档、活动方案生命周期、测试体系、测试工具和 CI，使后续需求以真实风险和行为合同为依据，避免继续累积过度设计、过度防御和过度测试，同时保留必要的跨功能回归保护。

实施只允许修改治理文档、测试文档、测试代码与帮助器、验证脚本和 CI workflow。产品代码在本方案中只读；静态盘点发现的路由覆盖、队列私有状态操作和 Store 职责问题由 [`ARCH-20260830`](../../../docs/已知问题与待做需求.md#arch-20260830代码架构整理与重复实现收口) 独立承接。

个人目录中的文档治理 Skill 是否继续作为项目标准来源仍为暂缓决定，不属于本方案。不得在本方案中修改、同步或卸载个人 Skill。

## 当前基线与问题

只读盘点确认当前项目并非单纯“测试太多”，而是测试职责、证明方式和治理成本失衡：

- 主项目 pytest 当前收集 357 项，其中 41 项为 Playwright；启动器另有 82 项，前端约有 40 项 Node 测试，T-DOC 规则自测有 32 项。数量本身不作为删除依据。
- 主 CI 在完整 Python 测试之外又选择约 200 项测试，涉及 129 个重复用例，其中 20 个用例在工作流中出现四次；同一性质被多个作业重复证明。
- `tests/test_repository_layout.py`、`tests/test_v060_plan_docs.py`、`tests/test_v060_release.py` 和 `tests/test_v070_frontend_architecture.py` 等文件包含根目录白名单、历史 PR 文案、固定 CI 矩阵形状和源码 Token 断言。这些断言中的一部分没有当前行为消费者。
- T-DOC 实现与规则自测的规模已经接近其治理的活动 Markdown 正文，并同时约束固定路径、导航拓扑、表格结构、待办状态和归档关系。
- `tools/t_project_isolation.py`、对应测试和 PowerShell 入口已经形成运行证据 schema、兼容读取、期限、摘要与 GC 协议；普通测试隔离与长期证据治理耦合过深。
- 没有发现统一的产品耗时门槛；现有并发 timeout 多数是安全上界。少量 Playwright 固定等待需要在受影响测试审计中改为可观察条件，但不得把机器耗时改造成新的性能门禁。

上述基线只用于定位治理问题，不形成文件数、测试数、行数或耗时阈值。

## 治理原则

1. **真实风险驱动**：规则和测试必须保护可说明的行为、合同、失败路径或平台边界；没有真实消费者时不建设治理设施。
2. **最小充分设计**：优先复用现有职责和入口，不为可能出现的未来需求预建抽象、兼容层、证据 schema 或模板。
3. **一项性质一次证明**：同一候选、环境和性质只保留一个权威证明；CI 并行不构成新增 Registry 项，也不应重复执行同一测试集合。
4. **行为优先**：固定文本、文件数量、源码 Token、历史状态、统一覆盖率百分比和机器耗时不能替代行为证明。
5. **保留真实回归网**：所有产品代码变化运行快速核心行为回归，再追加受影响测试；共享边界或影响无法可靠界定时扩大到完整 Python/Node 行为测试。
6. **主动解决不稳定性**：偶发失败先复现并修复竞态、隔离、状态泄漏或错误等待；不以重试、延长固定等待、永久跳过或降低断言掩盖。
7. **兼容真实入口**：保留实际供用户或开发者使用的命令、公开行为和确认存在外部消费者的顶层 CI 检查名；内部测试文件名、版本标签、矩阵形状和实现结构不承担兼容义务。
8. **治理不越界**：发现必须修改产品代码才能解决的问题时，形成精确待办或补充 `ARCH-20260830`，不在本方案中顺手修复。

长期防复发原则分别进入现有 `AGENTS.md` 和 `SoftwareTesting/PROTOCOL.md`，不新增 `GOVERNANCE.md`、强制设计检查表、测试映射文档或治理总入口。

## 实施切片

### 1. 文档、代码、测试与 CI 一致性

- 以当前活动真源为入口，对声明值、受支持入口、测试职责和 workflow 行为做一轮静态一致性核对；代码、配置、脚本和测试仅作为直接证据，不扩张成产品架构改造。
- 按事实所有者处理冲突：实现描述与当前行为不符时更新文档；产品合同与实现冲突时保留合同并登记代码问题；测试或历史材料不得反向定义当前产品事实。
- 只修复治理文档、测试职责、CI 接线和安全边界中的确定冲突。没有单独生成审计报告，处置结果直接进入对应真源和本方案实施记录。
- 产品代码问题不阻塞互不依赖的治理切片，但不得通过改测试或改文档把问题描述成已经解决。

### 2. 项目约束与长期文档

- 收敛 `AGENTS.md`：保留语言、授权、安全、停止发布和长期入口，加入本方案的最小充分、真实风险和无消费者不建设原则；删除会诱导固定规模、重复验证或超范围防御的规则。
- 保持需求、设计、字段契约、待办、测试 Registry 和运维手册各自承接事实，不建立新的并列真源或治理大全。
- 保留“待确认、待实施、实施中、暂缓”四种状态。T-DOC 只机械检查待实施/实施中事项存在有效方案链接、同一待办没有多份活动方案；固定表格措辞和普通归档登记问题不阻塞产品开发。
- T-DOC 仅保留 UTF-8/LF、必要入口、有效链接、轻量待办—方案关系和 Registry ID/入口有效性等稳定机械规则；移除固定目录拓扑、正文措辞、冗余导航数量和实现镜像断言。
- T-ARCHIVE 保持 `affected_only`，只在归档输入变化或方案关闭时检查归档自身的编码、链接、索引有效性和当前承接，不进入普通产品回归。

### 3. 测试体系与 Registry

- 为现有测试逐项识别其保护性质和直接消费者。保留行为、权限与安全、数据迁移、失败恢复、并发边界和真实平台合同测试；删除只锁定历史文案、源码写法、文件布局或已退出流程的断言。
- 有价值的性质若只由脆弱结构测试承接，先建立最小行为或边界测试，再删除旧断言；已经有等价证明时直接去重，不增加替代测试数量。
- 保留轻量测试 Registry，只登记真正独立的套件、用途、触发条件和入口。门禁只保证 ID 唯一和链接有效，不锁定四列表格、固定措辞或每次运行的 `test_id` 证据协议。
- 建立快速核心行为回归集合；模块专属测试按影响追加。共享持久化、认证、任务队列、公共 API 或前端公共运行时变化，以及影响无法可靠判断时，扩大到完整 Python/Node 行为测试。
- 不设置全局行覆盖率目标。每项新增或修改行为必须覆盖关键成功路径、合理失败路径和跨模块边界；覆盖不足按缺失行为说明，不用数字替代判断。
- 不稳定测试由实施者主动解决。若根因位于产品代码或不可用外部环境，准确记录阻断和代码待办；未经用户决定不得降低测试等级。

核心回归不创建新的 Registry ID 或 pytest marker。CI 中现有 `product-validation` 负责运行完整的非 integration、非 Playwright Python pytest，`frontend` 负责全部 JavaScript 语法与 Node 行为测试；二者共同构成每次产品代码变化的快速核心回归。`python` 只承担 Python 版本、源码安全边界、compileall 和 Ruff。共享 API、认证、持久化、任务队列或前端公共运行时发生变化，或者影响无法可靠界定时，再选择现有 `playwright` 阶段形成 T-PROJECT full；不通过新增清单、版本测试文件或固定用例数量维护核心集合。

本方案允许精确删除以下只承接历史文案、目录形状或源码 Token 的测试文件：

- `tests/test_repository_layout.py`
- `tests/test_v060_plan_docs.py`
- `tests/test_v060_release.py`
- `tests/test_v070_frontend_architecture.py`
- `tests/_v070_frontend_architecture_original.py`

`tests/test_v070_release.py` 删除后，以 `tests/test_delivery_policy.py` 承接仍有当前消费者的构建身份和“活动 workflow 不发布”安全性质；其余测试文件只做语义内修改，不在本方案中整文件删除。删除前先确认有价值行为由现有行为测试或新的最小边界测试承接，并同步移除 `tools/verify_source.py`、CI 和测试导入中的直接引用。

### 4. CI、隔离与运行证据

- 不删除 `.github/workflows/` 中任何文件。`ci.yml` 保留全部现有 job ID 以避免未知的外部检查名失效，并重新分配唯一职责：`python` 负责 Python 静态边界，`frontend` 负责 Node，`focused-validation` 只负责 T-DOC，`product-validation` 负责完整非浏览器 pytest，`playwright` 负责浏览器行为，`windows-validation` 负责 Windows Launcher 测试，`docker-validation` 只负责真实 Docker 构建与版本冒烟。删除后三个验证 job 中与 `product-validation` 重复的 pytest 选择，不改 `docker-image.yml` 与 `launcher.yml` 的现有独立平台职责。
- 普通本地与 CI 测试继续使用仓库外隔离目录、独立配置、临时数据、受控进程和浏览器 profile，但结果由控制台或 CI Artifact 承接。本地 `verify-source.sh` 在结果和诊断输出后精确清理本次 run；CI `run-playwright-phase.sh` 保留 run 到 `if: always()` Artifact 上传完成，由临时 runner 回收，不能在上传前清理。
- `tools/t_project_isolation.py` 只保留创建、验证和精确清理临时 run 的所有权与 containment 职责，供 `verify-source.sh`、`run-playwright-phase.sh`、`tools/config_sync.py` 和 `tools/playwright_runtime.py` 使用；移除结果记录、`test_id`、旧 schema、期限、摘要和 GC。同步更新 `tests/test_t_project_isolation.py`、`SoftwareTesting/SAFETY.md`、`SoftwareTesting/project/README.md`、`SoftwareTesting/PROTOCOL.md`、`scripts/README.md` 和 `docs/字段契约.md`。
- `scripts/windows/new-test-run.ps1` 保留现有 `Create`/`Record` 调用形状，但只接受 `T-DOCKER`，写入一份最小的 Docker 手工交接记录，不再兼容或创建 T-PROJECT 证据。`docs/运维/Docker镜像打包与离线交付.md` 与 `SoftwareTesting/docker/README.md` 是其直接消费者；既有仓库外证据保持原样，不读取、不迁移、不删除。
- 保留当前 Docker 手工交付入口的可观察用途；若简化会改变用户实际调用方式或外部 CI 检查名，而消费者无法从仓库确认，则在该项停止并申请差额决定。
- 不修改 Docker 或启动器构建链时，不运行真实 Docker 构建、启动器打包或对应正式认证。

## 验证计划

- 测试层级：各切片执行普通聚焦验证；最终候选按用户明确选择集中运行一次 T-PROJECT full，不提升为正式认证。
- 验证影响域：项目协作约束、活动与归档文档门禁、轻量 Registry、现有 Python/Node/Playwright 回归选择、测试隔离与证据入口、CI workflow；产品代码只作为只读证据。
- 具体验证项：
  1. 每个切片运行直接受影响的门禁规则自测、Python/Node 测试和静态解析；相同候选与性质不跨切片机械复跑。
  2. 文档变更运行对应的 T-DOC；归档输入未变化时不运行 T-ARCHIVE，变化或最终归档时只运行一次受影响组件。
  3. CI 修改执行 YAML 解析和测试选择对账，确认每个作业有唯一职责、核心回归未缺失且不存在重复选择。
  4. 最终候选运行一次 T-PROJECT full，包括 Python、Node 和隔离 Playwright；缺少既有依赖或浏览器时据实报告 `blocked`，不自行安装或下载。
  5. 最终执行 Markdown 链接检查和 `git diff --check`。真实 Docker、启动器构建、外部 CI、正式认证、commit、push 和 PR 保持未运行。

不建立永久“已知失败快照”。每个切片结束时受影响范围必须通过；无关的既有失败精确登记且不得冒充本切片失败，也不得以 baseline、skip 或重试把它永久合法化。

## 回滚

- 每个切片保持独立差异并在受影响验证通过后再进入下一切片；替代测试通过前不删除原断言。

- 目标文件出现无法与本方案安全合并的既有修改，或实施发现范围需要新增治理文档、测试套件或长期协议。
